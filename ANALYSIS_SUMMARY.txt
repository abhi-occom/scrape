                             MAIN PROCESS FLOW
================================================================================

10-STEP SCRAPING PROCESS:

1. SYSTEM INITIALIZATION
   - Flask server starts (app.py)
   - Config loaded with provider list
   - Dashboard served at http://localhost:5000
   - Output directories initialized

2. USER OPENS DASHBOARD
   - Web interface displays ISP providers
   - Left panel: Provider list + debug options
   - Right panel: Results, filters, stats
   - Each provider has "Scrape" button

3. CONFIGURE BROWSER (WITH CHECKBOX) ⭐ KEY FEATURE
   - System checks capabilities: Windows/Mac/Linux + Xvfb?
   - Checkbox "Show browser while scraping" enabled/disabled
   - User can select slow motion: 0-1000ms
   
   ☑ CHECKED = Visible Browser (you watch it happen)
   ☐ UNCHECKED = Headless Mode (faster, background)

4. SEND SCRAPE REQUEST
   - User clicks "Scrape" next to provider (e.g., Telstra)
   - Frontend sends: POST /api/scrape/telstra
   - Request body: {visible_browser: true, slow_mo: 500}
   - Timer starts: 00:00

5. BROWSER INITIALIZATION
   - Playwright launches Chromium browser
   - If visible: Browser window opens on desktop 👀
   - If headless: Browser runs in background
   - Stealth features applied (anti-bot detection)
   - Slow motion configured (500ms per action)

6. NAVIGATE TO WEBSITE & RENDER
   - For Telstra: 5 pages are scraped
     - /internet/plans (NBN plans)
     - /internet/5g-home-internet (5G plans)
     - /internet/starlink (Satellite)
     - /internet/opticomm-plans (Opticomm)
     - /small-business/internet (Business)
   
   - Each page: page.goto(url) → page.wait_for_timeout(6000)
   - You see real-time page rendering if visible browser
   - JavaScript executes, dynamic content loads
   - Network requests shown in DevTools (F12)

7. EXTRACT PLAN DATA
   - CSS selectors query elements (e.g., plan cards)
   - Extract text and attributes from matched elements
   - Build plan objects with: name, price, speed, network_type
   - Example: 20 plans extracted from Telstra
   
   Selectors used:
   - Plan headers: h3.tcom-fixed-plan-card-header__headline
   - Prices: [data-fixed-plan-card-price]
   - Download speeds: [data-tcom-fixed-plancard-dsq-evening-download]
   - Upload speeds: [data-tcom-fixed-plancard-dsq-evening-upload]

8. CAPTURE SCREENSHOTS
   - Each page's rendered state saved as PNG
   - Location: output/screenshots/
   - Examples:
     - telstra_plans_2024-01-20T10:30:00.png
     - telstra_5g_home_2024-01-20T10:30:15.png
     - telstra_starlink_2024-01-20T10:30:30.png
   
   - Shows: actual page layout, plan cards, prices, networks
   - Used for validation: Compare with actual website

9. VALIDATE & CLEAN DATA
   - Each plan checked for:
     ✓ plan_name: must exist, non-empty
     ✓ price: must be positive number
     ✓ download_speed: must be positive integer
     ✓ network_type: must be valid
   
   - Invalid plans removed and logged
   - Valid plans proceed to save

10. SAVE & OUTPUT RESULTS
    - 4 formats saved:
    
    A. JSON: output/scrape_isp_telstra/json/telstra_all_plans.json
       [{"plan_name": "...", "price": 89.0, ...}, ...]
    
    B. CSV: output/scrape_isp_telstra/csv/telstra_all_plans.csv
       provider,plan_name,network_type,download_speed,price,...
    
    C. Database: INSERT into plans_current table (MySQL)
       (provider_id, plan_name, price, speed, ...)
    
    D. Log: output/logs.json
       {"timestamp": "...", "status": "success", "plans": 20}
    
    - Timer stops: ✅ Completed in 45s
    - Dashboard updated with results
    - User can download, filter, sort

================================================================================
                    CHECKBOX WORKFLOW: "Show Browser While Scraping"
================================================================================

THE CHECKBOX IS THE KEY FEATURE FOR VISUAL VALIDATION:

BEFORE SCRAPING:
   1. User opens dashboard
   2. JavaScript: checkCapabilities()
   3. Endpoint: GET /api/capabilities
   4. System checks: Windows? Mac? Linux + Xvfb?
   5. Result: visible_browser = true/false
   6. If true → Checkbox ENABLED ✅
      If false → Checkbox DISABLED ❌ + warning

WHEN UNCHECKED ☐ (Default - Headless Mode):
   - visible_browser = false
   - Browser runs in background (invisible)
   - Faster execution
   - Good for production/batch scraping
   - Screenshots still captured

WHEN CHECKED ☑ (Visible Mode):
   - visible_browser = true
   - Browser window opens on desktop
   - You watch real-time page loading
   - Slow motion applies (500ms per action)
   - Perfect for debugging & validation
   - Can use DevTools (F12) to inspect
   - Screenshots prove data availability

SLOW MOTION DROPDOWN (0-1000ms):
   - 0ms (Off) = Normal speed
   - 100ms = Slow
   - 250ms = Slower
   - 500ms = Very slow (Recommended)
   - 1000ms = Slowest (1 sec per action)
   
   - Each action pauses for selected time
   - Good for watching page load and taking screenshots

REQUEST SENT WHEN SCRAPING:
   POST /api/scrape/telstra
   {
     "visible_browser": true,  ← from checkbox
     "slow_mo": 500            ← from dropdown
   }

BROWSER CONFIGURATION:
   configure_browser(
       headless=not visible_browser,  # False = Visible
       slow_mo=500                    # 500ms delay
   )

RESULT IN BROWSER:
   ✓ Chromium window opens
   ✓ Real-time page navigation
   ✓ Slow motion applied to each action
   ✓ DevTools available (F12)
   ✓ Network tab shows all requests
   ✓ Console shows JavaScript logs
   ✓ You can inspect selectors

SCREENSHOTS:
   ✓ Automatically captured after each page loads
   ✓ Saved to: output/screenshots/
   ✓ Show exact page layout
   ✓ Prove data was available
   ✓ Easy to compare with actual website

VALIDATION PROCESS:
   1. Take screenshot of Telstra plans page
   2. Compare with actual: telstra.com.au/internet/plans
   3. Do prices match? ✓
   4. Do plan names match? ✓
   5. Do speeds match? ✓
   6. Is network type correct? ✓
   → Data is accurate! ✓

================================================================================
                         ANTI-BOT DETECTION
================================================================================

The system includes sophisticated stealth features:

   ✓ User-Agent rotation (appear as normal browser)
   ✓ Headless detection removal (remove --headless flag)
   ✓ Automation indicator removal (disable "navigator.webdriver")
   ✓ Request header spoofing (custom headers)
   ✓ Timing randomization (variable delays)
   ✓ CDP protocol (Chrome DevTools Protocol)
   ✓ Plugin removal (disable plugins)
   ✓ Disable dev-shm (improve compatibility)

See: utils/stealth.py for implementation
